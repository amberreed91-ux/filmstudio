# Multishot Integrity Forensic Audit — Phase 6 Gate

**Audit mode:** read-only source/artifact inspection. No generation, provider submission, database write, source/test/fixture edit, or credit-consuming action was performed for this audit.  
**Scope:** current `scene_production_pipeline` → `RenderService` → Runway Model Router path, plus the saved scene_002 preflight evidence.  
**Interpretation note:** repository evidence uses “DRE” as the character name in scene_002, not as a defined lock-system acronym. This report treats “DRE lock” as DRE’s character-reference lock; if it means another lock, no corresponding DRE-specific concept was found in the inspected code.

## 1. Executive conclusion

**The multishot production contract is not trustworthy enough to pass Phase 6.** There are real protections around shot ownership, readiness, approved references, camera provenance, prompt budgets, and persisted Router contracts. They do not close all links from canonical script truth to the exact final request.

### Prompt length and content-loss finding

`StoryboardBlueprintService._build_provider_neutral_prompt` still passes `max_length=512`, but `build_shot_aware_prompt` documents that argument as deprecated/ignored and returns the assembled prompt without truncating. The storyboard builder then prepends shot-plan language, generated scene segment, rationale, and locked appearance block. Scene_002’s stored prompts are 2,994–3,200 characters in the approval artifact, consistent with no 512-character clipping.

The **512 constant is not globally gone**: `_truncate_to_budget` and the standalone `build_slotted_prompt` still use it for legacy slot/preview surfaces; direct-provider prompt policy also uses a conservative 512 ceiling. Those paths either run in lossless collection mode for supported assembly or must fail readiness rather than truncate for prepared contracts. The prepared Router policy is 20,000 characters and preserves source text; the Router request builder independently rejects lengths above its input cap. Thus the old canonical-prompt 512 cut is not the present prepared multishot production breakpoint.

However, “not truncated” is not equivalent to “lossless decomposition.” `_segment_scene_text` chunks non-heading lines approximately evenly; the builder’s render prompt includes at most two classified lines from the chosen segment, and a final segment absorbs leftovers. The generated board prompt may therefore omit scene beats or place a line in a shot without creator-authored dialogue assignment. Existing prompt-integrity detection finds ellipses and severed terminal fragments but explicitly cannot identify a cut ending in valid punctuation. Evidence: [shot_prompt_builder.py](studio-backend/app/services/shot_prompt_builder.py#L120-L165), [builder and max_length contract](studio-backend/app/services/shot_prompt_builder.py#L392-L535), [prompt_integrity.py](studio-backend/app/services/prompt_integrity.py#L1-L55), [non-truncation tests](studio-backend/tests/test_storyboard_prompt_no_truncation.py#L1-L190).

## 4. Exact breakpoints

1. **No runtime script-to-scene lineage check — `UNKNOWN/FAIL`.** Scene selection uses project scene rows; scene versioning hashes `scene_id`, `heading`, `text`, and `updated_at`, not the canonical project `script_text` hash or parser span/source IDs. See `GenerationContextService.scene_version` in [generation_context_service.py](studio-backend/app/services/generation_context_service.py#L248-L263), and the selected scene in [scene_production_pipeline_service.py](studio-backend/app/services/scene_production_pipeline_service.py#L391-L425). The audit artifacts establish a particular scene_002 hash history, not an invariant checked on every request.

2. **Setting ID provenance is unchecked — `UNKNOWN`.** `reference_validation._setting_id` takes the first explicit `setting_id`/`location_id`/`environment_id` and treats the string as identity; it does not resolve a canonical setting record. Approved setting assets are then selected by that ID. The saved scene_002 evidence reports `setting scene_002`, so the approved reference gate blocks, but the source of that identity string is not proven by this resolver. See [reference_validation.py](studio-backend/app/services/reference_validation.py#L430-L510) and [dry-run](studio-backend/reports/multishot_dryrun_payload.json#L1-L25).

3. **Shot content is segmented heuristically — `FAIL`.** `_segment_scene_text` distributes non-heading lines in approximately equal chunks; `build_shot_aware_prompt` filters each chunk and selects at most two action/dialogue lines. `_build_initial_shots` adds auto-derived framing/rationale. The transformation has no per-script-line identity map and cannot prove every canon beat lands in the intended approved shot. See [shot_prompt_builder.py](studio-backend/app/services/shot_prompt_builder.py#L120-L165), [prompt builder](studio-backend/app/services/shot_prompt_builder.py#L392-L535), and [storyboard initial shots](studio-backend/app/services/storyboard_blueprint_service.py#L1050-L1150).

4. **Unassigned dialogue is converted to silence — `FAIL`.** In `prepare_scene_batch`, structured per-shot `dialogue_lines` take precedence. Otherwise the pipeline reads only rows already tied to the shot; scene-level extraction is allowed only when `len(shots) == 1`. It then freezes the empty result, whose `silence` flag is true. The frozen handoff checks hash, scene/shot IDs, shape, and placeholder pattern, but not complete coverage/uniqueness against canonical screenplay dialogue. See [scene_production_pipeline_service.py](studio-backend/app/services/scene_production_pipeline_service.py#L637-L689) and [generation_contract.py](studio-backend/app/services/generation_contract.py#L56-L126).

5. **`execution_summary.dialogue_lines` is not intrinsically canonical.** `dialogue_authority` documents historical synthetic “carries the beat…” rows and filters that exact placeholder pattern. Other non-placeholder supplied/stored rows are accepted. Thus it is a filtered projection / creator-supplied source, not by itself proof that each row is a verbatim line from current `script_text`. See [dialogue_authority.py](studio-backend/app/services/dialogue_authority.py#L1-L158). Scene_002 reports document ten extracted canonical screenplay lines but all were unassigned on the reviewed board; there is no run-time all-ten reconciliation.

6. **No shot-level character-reference intersection — `UNKNOWN`.** `resolve_scene_reference_requirements` resolves characters from the scene record and `reference_binding_for_requirements` includes their canonical references. The batch does not visibly intersect that binding with each board shot’s `intent.character_focus`. A shot can receive all scene-cast references even if its own shot intent is narrower. ## 5. Existing protections

These are already implemented and should be preserved rather than rebuilt:

- **Approved/current storyboard gate:** `scene_render_inputs` requires current version == approved version, nonempty shots, and renderable approved shot status. A draft or stale version blocks.
- **Shot ownership:** both the encoded scene in `shot_id` and any explicit `scene_id` must match the selected scene. Duplicate shot IDs fail. Legacy scene execution ledger is explicitly excluded from shot-source selection.
- **Prepared-batch freshness:** prepared snapshot is one-use, expires, binds project/scene/provider, and is compared to current full scene and shot-source fingerprints at consumption and again before each shot. Stale source fails closed.
- **Generation-context freshness:** scene, board, reference, shot, camera, expected scene ID, and expected shot ID are checked. AI camera suggestions create blockers, not approval.
- **Prompt integrity and provider budget:** historical ellipses/severed fragments in board prompts block. Prepared prompts are preserved and checked against policy; overflow sets `needs_review` or fails request construction rather than truncating the canonical contract.
- **Dialogue placeholder quarantine:** known synthetic template rows are filtered from production dialogue. Frozen handoff has a content digest, explicit scene/shot identity, silence/list consistency check, and is re-verified before audio/assembly.
- **Canonical setting/reference gates:** human-readable location is not promoted to an ID; each required character/setting needs an approved canonical anchor. Candidate/rejected references and wrong-owner refs fail.
- **Reference binding integrity:** ordering, URI, target IDs, roles/categories, approval state, canonical flag, project identity, consistency payload semantics and digest are checked; Router refuses unrepresentable/over-limit refs rather than dropping them.
- **Camera provenance:** generic fallback camera plans are rejected; approved storyboard camera requires exact board-shot identity; AI provenance cannot carry an authoritative plan; plan digest and target shot are verified.
- **Frozen Router contract:** job creation validates contract/manifest and persisted round trip; submission reloads a persisted Router job, validates provider/job/shot identity, fingerprints, contract digest and creative values. The adapter builds from the frozen contract, not mutable input payload fields.
- **Provider identity safety:** provider substitution protection is a separate prerequisite and is not treated here as proof of multishot correctness.

Tests provide evidence for these code paths but do not all establish production-level behavior. In particular, tests that replace `render_service`, `audio_service`, storage, or `_runway_router_request` prove only their asserted local contract under those fakes. The Router tests with a captured mocked HTTP function prove the body passed to that seam, not that Runway accepts or behaves as expected. No hosted call was made or is claimed.
