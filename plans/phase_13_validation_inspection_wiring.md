# Phase 13: Validation Inspection Wiring - Architecture Plan

## Executive Summary

**Recommended Next Slice**: Wire the existing `RenderValidationReport` (Phase 9.5) to the frontend inspection panel, completing the execution→validation→user-observation chain. This is the smallest safe step that adds user value without modifying authority boundaries.

**Why This Is The Safest Move**:
- Phase 9.5 already defines `RenderValidationReport` as strictly advisory
- Phase 12 already established `RenderExecutionSummary` as observational only
- No new authority paths, no autonomous loops, no Co-Director promotion
- Frontend/backend connection is verified (proj-001 loads real data)
- QA selectors are in place for validation inspection panel

## 2. Recommended Phase 13 Slice

### Scope: Validation Inspection Panel Wiring

**What**: Connect existing `RenderValidationReport` to frontend `ExecutionSummaryInspectionPanel` (or create if not exists)

**What NOT To Do**:
- ❌ Do NOT make validation reports block execution
- ❌ Do NOT auto-retry renders based on validation
- ❌ Do NOT promote advisory issues to canonical truth
- ❌ Do NOT allow Co-Director to act on validation findings
- ❌ Do NOT create autonomous loops

### Implementation Boundaries

## 5. Risks

### Risk 1: Validation Findings Leaking Into Authority

**Mitigation**: Static analysis tests that fail if `RenderValidationReport` or `validation_issues` appear in:
- `authority_hierarchy.py`
- `director_evaluator.py`
- `orchestrator.py`
- `co_director_*.py` services

**Severity**: High if occurs

### Risk 2: Frontend Creating Retry Loops

**Mitigation**: QA selectors and tests verify no auto-retry on validation severity. Execution summary panel is display-only.

**Severity**: Medium

### Risk 3: Co-Director Consuming Validation

**Mitigation**: Phase 11 containment tests already guard this. Verify `co_director` services don't import `render_validation_service`.

**Severity**: Low (already guarded)

## 6. Go/No-Go Criteria

### Go Criteria (ALL must be true)

- [ ] `GET /render/{job_id}/validation` returns `RenderValidationReport`
- [ ] Report contains `is_advisory=True` for heuristic issues
- [ ] No `POST`/`PUT` endpoint accepts validation findings
- [ ] `test_validation_report_never_consumed_by_authority` passes (static scan)
- [ ] `test_co_director_does_not_import_validation` passes
- [ ] Frontend panel renders validation issues as read-only
- [ ] No retry/autonomous action buttons in validation panel
- [ ] Existing Phase 11 containment tests still pass
- [ ] proj-001 still loads real backend data

### No-Go Criteria (ANY triggers pause)

- [ ] Validation report introduces blocking/rejecting behavior
- [ ] Co-Director services gain new imports of validation code
- [ ] Authority hierarchy adds validation-based decision paths
- [ ] Frontend creates auto-retry based on validation severity
- [ ] Any existing test regression

## 7. Out of Scope for Phase 13

- **Phase 15**: Validation trend analysis across scenes (requires advisory aggregation)
