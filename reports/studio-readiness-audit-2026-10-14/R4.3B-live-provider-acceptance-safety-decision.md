### 3b. The R4.0A probe: `dryRun:true` routed video request with 5 referenceImages

Source: R4.0A §7.1 ("an authorized `dryRun: true` probe with 5 referenceImages … Requires credentials + explicit authorization") and §8.2; validation snippet in `FINAL_REPORT_20260928.md` ("How to validate once the router config exists": `submit_runway_router_video_render("probe motion", …, dry_run=True)`).

Two invocation depths exist. The report's snippet is the raw provider-function depth; the production depth is the full adapter submit. Both are traced:

**Depth 1 — raw provider function** (`submit_runway_router_video_render(..., dry_run=True)`):

1. Entry: direct Python call (no route, no job, no preflight, no confirmation, no authorization service).
2. Config/credential loading: `get_runway_router_api_key()` (env-first `RUNWAY_API_KEY`/`RUNWAYML_API_SECRET`) or in-memory `api_key` kwarg; `get_router_config_id()` (`RUNWAY_ROUTER_CONFIG_ID` or default `studio-production-router`); base URL `get_runway_router_base_url()` (default `https://api.dev.runwayml.com`).
3. Request construction: `build_runway_router_video_request(...)` — prompt non-empty check, 20,000-char cap, duration/resolution/seed validation, **capacity gate: `len(first_frame) + len(references) > 4` raises `RunwayRouterReferenceIncompatibility("reference_limit_exceeded")` before any network call**; role gate (`first`|`last`|`reference` only); at-most-one `first`/`last`. `body = {configId, input, dryRun: true}`.
4. Network dispatch: `_runway_router_request(POST {base}/v1/generate/video, payload, api_key)` — `Authorization: Bearer <key>`, `X-Runway-Version: 2024-11-06`, with queue-lease re-check at the HTTP boundary.
5. Provider-side effects: per the module contract, a dry run "runs the full routing pipeline and returns the decision and an ESTIMATED cost without creating a task, generating, or billing." Response parsed by `parse_runway_router_response`: dry-run branch requires `dryRun is True` and **no** task id (an id on a dry run raises); returns `{status: "dry_run", url: None, meta: {resolved_model, resolved_settings, resolved_input, estimated_cost_credits, ...}}`.
6. No polling on the dry-run branch (polling `_poll_runway_task` runs only for live responses: bounded attempts + elapsed-time deadline, task-id match enforced). No persistence (the function returns a dict; it writes no job row, no metadata — persistence happens only in the adapter layer).

**Depth 2 — full adapter submit** (`RunwayRouterAdapter`, `app/adapters/__init__.py`):

1. Entry gate `:1872` (authority resolution + durable identity check) and just-before-send recheck `:2394`.
2. Declared-projection resolution `:1740-1840`: canonical bindings from contract, authorization-record match, projection build — then, **for any local (non-https/runway/data-image) selected reference, `materialize_selected_ephemeral` uploads canonical bytes via `POST /v1/uploads` allocation + multipart transmit** (`runway_ephemeral_upload.py:298-460`). This runs before `_run_sync` and therefore **before and regardless of the dry-run flag**.
3. `_run_sync(dry_run=True)`: sets `request_payload["dryRun"] = True`, asserts wire references equal the authorized projected selection, calls the Depth-1 function. On the non-protected path the adapter first issues this dry-run preflight, applies local cost-gate controls to the advisory estimate, then issues the **live** `_run_sync()` (dry_run=False) — i.e., a full adapter invocation always proceeds to a live submission unless the dry-run preflight fails or the estimate gate refuses. There is no adapter mode that performs only the dry run and stops (the protected Scene002 path performs only the live request and never a dry run).

**The 5-reference consequence (both depths):** the R4.0A probe specifies 5 referenceImages. Current code raises `reference_limit_exceeded` at step 3 (Depth 1) / the projection capacity check (Depth 2) **before any network call**. The probe as literally specified cannot reach the provider at all — it exercises the local fail-closed gate, which is already test-proven, and returns zero provider information. This is a finding about the proposal, not the code: the code is behaving exactly as R4.0A §6 recommended ("explicit reject … fail-closed").

## 7. Proposed acceptance protocol (supportable only after §8 blockers clear)

The following is a proposal for a **separate, explicitly authorized task**. It is not authorized by this report and must not run under decision B.

- **Entry point:** Depth 1 only — direct call to `submit_runway_router_video_render(..., dry_run=True)` (and, if image scope is wanted, `submit_runway_router_image_render(..., dry_run=True)`) from a one-shot script or REPL. **Forbidden:** full adapter submit, any route (`POST pipeline/generate`, `POST /jobs`), queue worker, retry/revision flows — all proceed to live submission by design.
- **Scope:** one generic (non-Scene-002) shot with a frozen contract of **1–4 references, all `https://` provider URIs** (no local bytes, so no ephemeral materialization path is reachable). Suggested: a synthetic test shot carrying the minimum references needed to prove forwarding order — never production creative material on the first run.
- **Preconditions (all must pass, in order):** (a) credentials provisioned out-of-band and router slug re-verified present via read-only `GET /v1/routers` list only; (b) local builder reproduction of the exact body via `build_runway_router_video_request(..., dry_run=True)` with byte comparison to the intended payload; (c) documented list of every URI and the full prompt text to be transmitted, with creator sign-off on external transfer; (d) explicit authorization naming this entry point, this scope, and the dry-run-only mode.
- **External material sent:** full prompt text, all reference image URIs (+ roles), duration/resolution/seed/aspect, config slug. No local bytes (by the https-only constraint).
- **Expected provider-side effects:** routing evaluation only — no task, no billing (provider-claimed; capture the response to check, not to trust). Possible charges: none expected; treat any `id` in a dry-run response as a stop event (the code already refuses to poll it — `dry_run_response_mismatch`).
- **Job creation:** none is expected at either end — no local job row (Depth 1 writes nothing), no provider task (dryRun contract). Verify by asserting the response has `dryRun is True` and no `id`.
- **Job identification:** not applicable — no job should exist. Capture the full response (`resolved_model`, `resolved_settings`, `resolved_input`, `estimated_cost_credits`, `no_eligible_model` pipeline/emptiedBy if present) as the evidence artifact. Do not search production state for corroboration.
- **Local evidence to capture:** the exact built body, the raw response, parsed routing fields, wall-clock time, config slug, and credential source (name only, never the value).
- **Success criteria:** `status == "dry_run"`, routing fields populated, estimated cost present, and (for a ≤4-ref shot) no `no_eligible_model`. **Failure:** `router_config_not_found` (config still absent), `no_eligible_model` (routing rejects the shape — evidence, not error), any transport error. **Inconclusive:** any response that contradicts the documented schema (e.g., id on a dry run).
- **Stop conditions:** any live-task id returned; any prompt to "retry as live"; any code path that imports the adapter submit; any request for production creative material; any missing precondition. On stop: halt, preserve the artifact, report — do not retry.
- **Duplicate/extra-submission prevention:** Depth 1 performs exactly one POST and never polls or retries (no retry loop exists on this branch; `no_eligible_model` and 404 raise as failures, not retries). Forbid wrapping the call in any retry helper; forbid falling back to the adapter or a direct-model endpoint on `no_eligible_model` (the code already fails closed — keep it that way).
