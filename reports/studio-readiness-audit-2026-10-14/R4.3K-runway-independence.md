## 1. Intended provider-independent architecture

Recorded as the target; §5 marks each element verified / partial / gap:

**A. Studio owns production truth.** FilmLevelMemory, FilmStructure,
CreativeSpine, explicit scene input, approved creator decisions, approved
references, frozen shot bindings, and generation contracts are canonical.
Providers and derived intelligence must not silently change identity,
appearance, wardrobe, setting, dialogue, shot requirements, references, or
creative decisions. *Status: enforced (verified this phase, §4 I-1).*

**B. Studio owns production authorization.** The Production Integrity Gate is
the final boundary; the Integrity Engine is advisory only. READY results,
provider responses, HTTP statuses, and job ids are not authorization. All
required checks fail closed at creation, submission, and adapter boundaries.
*Status: enforced (tested, network-blocked, §8).*

**C. Providers are replaceable execution systems behind explicit contracts.**
Adapters translate an authorized Studio contract into a provider-specific
request and own provider identifiers, formats, capabilities, errors, and
status. Capability differences are explicit rejections or creator decisions —
never silent reference removal, requirement weakening, identity substitution,
or creative-decision alteration. No second abstraction layer is created: the
`RenderProviderAdapter` registry + `generation_contract` + projection policy
already is the contract architecture. *Status: partially enforced —
canonical model is provider-clean, but the pipeline mirrors one provider's
capacity number (§4 C-2) and default-provider fallbacks name Runway (§4 C-4).*

**D. Capability validation is explicit and fail-closed.** If a provider cannot
meet a shot's requirements, Studio rejects the shot or batch before any job
is created. *Status: enforced for the current provider (tested); the
four-reference ceiling lives in Studio's contract, not only in the Runway
projection (§2C below) — so Runway's limit currently defines what Studio can
authorize.*

**E. Studio orchestrates; the provider executes.** Studio controls preflight,
authorization, execution state, reconciliation, validation, and delivery. The
provider returns evidence. The router stays model-agnostic: no hidden
ranking, automatic fallback, or silent provider selection. *Status: enforced
on the router path (tested); reconcile-before-retry closes the ambiguity leg
at mocked level (R4.3E, re-verified §8).*

**F. Failure is a first-class production outcome; evidence is preserved.**
Timeout ambiguity never implies non-creation; retry requires reconciliation
or idempotency evidence first; no automatic retries or fallback providers.
Authorization → submission → provider identifiers → outputs → validation →
delivery records form a durable, project-scoped chain. *Status: established
through delivery handoff (tested); provider-side leg unverified (§7).*

### (b) Coupled but fixable within existing contracts

- C-2 (carried, confirmed) Preflight mirrors one provider's constraint:

- C-4 (new this phase — R4.3D §4 did not itemize these) Default-provider
fallbacks name Runway: `app/config.py:29` (`render_video_provider: str =

- C-3 (carried) `router_execution` metadata shape

execution-metadata shape. Fix within existing contracts: per-provider
execution-evidence namespaces.
- F-1 (carried, Decision C deferred) Dry-run transport failure carries
`submission_attempted` and blocks later resubmission despite provable
non-creation — fail-closed imprecision, availability-only impact.
