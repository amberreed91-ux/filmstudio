## b. The seed lock

**What it does, where, for which jobs, when** (Code-inspected):
`RenderService.submit_job` (`render.py:~4715-4751`) persists the job
(`_persist_job`), then — for non-contract-only jobs only
(`if not is_contract_only(job) and _storage and ...seed... is None`,
`:4724`) — reuses the stored shot seed or generates and saves a fresh one
(`SEED_REUSED` / `SEED_GENERATED` stage logs, `:4729-4738`), writes it into
the **in-memory** `input_payload.parameters["seed"]` (`:4740-4743`), and
calls `adapter.submit_job` (`:4751`) with **no durable write in between**.
The adapter's entry authority check compares the in-memory job against the
durable row field-for-field (`production_authorization_service.py:84-92`:
`input_payload.model_dump() !=` durable → `durable_render_job_identity_mismatch`),
so any job whose frozen seed is null is denied before any frozen-proof check
— exactly the A2 production-entry finding (`differing_input_keys=["parameters"]`,
durable seed null vs in-memory seed; Mocked/Tested in A2 §2).

**What depends on it:** the `SEED_REUSED`/`SEED_GENERATED` audit trail;
per-shot seed persistence (`storage.py:7651-7685` `save_shot_seed` /
`update_shot_seed_lock`); Scene 002's protected-seed tests
(`test_scene002_contract_only.py:225`, Tested in the v1 suite); the retry
service's *fresh-seed* strategy, whose code comments state seed locking does
**not** guarantee reproducibility, citing `SEED_NON_DETERMINISM_FINDING.md`
(Code-inspected: `render_retry_service.py:4-10`, `:1020-1021`, `:1084-1087`) —
the cited memo is **absent from this tree** (Unverified as an empirical
claim here; the retry behavior it motivated is Code-inspected).

**Is it meaningful for the router path?** Partially. The wire accepts a seed
(`build_runway_router_video_request(..., seed=...)`, `:514`), so *a* seed
value remains a concrete generation input worth freezing. But the lock's
reproducibility rationale is weakened by the repo's own non-determinism
finding (code comments, Unverified memo), and its current placement —
mutating the authorized snapshot after the last durable write — directly
violates the principle that an authorized request is immutable after
authorization. The seed must be settled **before** the durable snapshot the
authority check compares, full stop.

**Options evaluated:**

1. **Apply the seed before freeze.** Strongest against the principle: the
   frozen contract, the durable row, and the wire all carry the same seed
   from birth. Cost: moves a storage side effect (shot-seed read/generate)
   into the pipeline freeze path, which is currently pure; needs care so
   preflight stays side-effect-free (generate at creation, not at prepare).
2. **Skip the seed lock for router jobs; record the decision in evidence.**
   Narrow and honest given the non-determinism finding, but surrenders the
   seed audit trail (`SEED_*` logs, shot-seed rows) and leaves `seed=null`
   to provider default — a behavior change to generation inputs that needs
   its own creator-facing rationale. Weakest on traceability.
3. **Keep the lock but re-capture durable identity afterward.** As a bare
   re-persist this **weakens the check**: any tamper between creation and
   the re-persist would be laundered into the new durable snapshot by
   construction. It is acceptable **only as a constrained re-persist**:
   assert the *only* durable-vs-memory difference is `parameters.seed`
   (null→int), then persist, then dispatch. That preserves the anti-tamper
   guarantee for every other key while legalizing exactly one declared
   mutation.

**Recommended ruling: option 1, fallback option 3-constrained**
(rationale in §e). Either preserves the guardrails; option 2 is not
recommended.

## d. `rejected_environment_ref_ids`

**Why the declared path requires a non-empty list** (Code-inspected:
`runway_reference_projection.py:1017-1020`): the record value is read as
`authorization.get("rejected_environment_ref_ids") or ()`, then
`isinstance(..., list)` is required — so `[]` collapses to the tuple `()`
and **fails**. Counter-intuitive but load-bearing, observed live in prior
sessions (Mocked). The list's functional role: any rejected id present in
the canonical inputs fails closed (`rejected_reference_present`,
`:1072-1081`; Tested: `test_runway_reference_projection_generic.py:315`).
The invariant it plausibly protects: **proof that a selection ran** — the
record names both what was chosen (`authorized_environment_ref_id`) and what
was considered-and-excluded, so the authorized environment cannot have been
defaulted or substituted without evidence.

**Where it was introduced / what justifies it:** **Unverified** via git —
`runway_reference_projection.py` is an **untracked file** (no history;
verified via `git status`/`git ls-files` this session), so no introducing
commit exists in this tree. Earliest documentary justification: the R3.2
generic-projection report's rejected/wrong/stale authorization negative
controls (`R3.2-generic-scene-runway-projection.md:59-62`, Code-inspected)
and the generic v2 suite's `_gauth` (non-empty list, `:89`) plus the
rejected-present test (`:315`, Tested suite green).

**Does a legitimate generic scene with one approved environment and no
rejected candidates exist?** Yes — it is the *normal* case, not an edge.
The pipeline's own authorization-shaped builder returns
`"rejected_environment_ref_ids": []` for a single explicitly selected
setting (`scene_production_pipeline_service.py:2180-2205`, Code-inspected:
single-selected-setting validation at `:2145-2158`, empty list at `:2201`).
A scene with exactly one canonical environment and no alternates has no
honest rejected identities to name. Under today's rule, F5 would have to
**synthesize** rejected ids to satisfy the type check — minting selection
evidence that never occurred. That is worse than the gap it pretends to
close.

**Options for the generic record shape:**

- **(A) Keep the non-empty requirement.** F5 must then source *genuine*
  rejected candidates (e.g. non-selected setting rows for the scene) and
  prove per-scene they exist. Evidence needed: a query showing alternate
  setting rows are available wherever generic dispatch is allowed; scenes
  without alternates stay non-dispatchable (fail-closed, but possibly
  permanently). No check changes; no authority-semantics change beyond F5.
- **(B) Allow `[]` with an explicit `selection_basis`.** E.g.
  `selection_basis: "single_canonical_environment"` alongside the
  unchanged exactly-one-approved-row, binding-equality, digest, fingerprint,
  and version-identity checks. Evidence needed before relaxing: negative
  controls proving substitution still fails (wrong-env authorization,
  foreign `project_id`, stale digest, tampered binding, non-empty-list
  rejected-present case, and the new `[]`-with-plural-candidates case must
  fail). This **touches authorization semantics** (it redefines what counts
  as authorized selection evidence) and therefore needs the same owner
  approval as F5 itself.

**Do not relax the check without (B)'s controls.** The non-empty rule is
currently the only structural evidence that a choice occurred; removing it
bare without controls would let a defaulted environment pass as selected.

## e. Recommended rulings, sequencing, effort, decisions

### Ruling F7 (item 1 — creation stores the three frozen dicts)
**Recommend: store more (direction A).** `create_job` writes the frozen
`scene_coverage` / `scene_coverage_shot` / `dialogue_handoff` into the
persisted `RenderJobInput.parameters`, and gains the missing creation-time
parameters round-trip check for non-contract-only jobs (closing the
`:2644-2652` asymmetry). Trade-offs: slightly larger stored rows (JSON blob,
no migration) vs `compare-less`, which would delete anti-tamper coverage the
tamper tests prove valuable. Guardrails preserved: authorization semantics
untouched (inputs are mutable by design; writing frozen values is
traceability), stored contracts untouched, schema untouched, Scene 002 path
improves (it is broken here too). Files: `render.py` (~:2516-2548,
`:2644-2652`). Negative controls: §c list.

### Ruling F9 (item 2 — seed lock vs durable identity)
**Recommend: option 1 (seed settled before the durable snapshot — generate
at creation when the frozen seed is null), fallback option 3-constrained
(assert-only-`parameters.seed`-differs re-persist before dispatch).**
Reject bare re-persist (launders tampering) and option 2 (surrenders the
seed trail). Guardrails: the durable snapshot the authority check compares
must equal what the provider receives; `SEED_*` logging and shot-seed rows
stay. Files: `render.py` (`create_job` seed defaulting; `submit_job`
`:4723-4751` → constrained re-persist or removal after option 1).
Authorization semantics: not minted, but ordering-sensitive — the mutation
must precede the snapshot. Stored contracts: seed becomes part of the frozen
input shape for null-seed batches (new rows only; existing stored jobs
unaffected — none were found persisted in prior sessions). Negative
controls: null-seed batch submits without identity denial; post-creation
non-seed param mutation still denied; seed-only difference still passes;
contract-only path unchanged (guard already skips it).

### Ruling F8 (item 3 — creative-parameters parity)
**Recommend: pipeline freezes `{}` creative parameters for router jobs,
plus a creation-time evidence entry** (e.g. `metadata.selection_evidence`:
which coverage/handoff/reference carriers each dropped key resolved into),
**and** a guard that the `{}` rule never applies to non-router providers.
Trade-offs: tiny pipeline change, no auth/schema/Scene 002 touch, vs
enforcing a `:784`-equivalent on the declared path — which would merely move
the refusal without giving the creator any new information. Guardrails: the
no-silent-drop principle is satisfied by *explicit, evidenced* resolution,
not by keeping redundant copies; preflight stays fail-closed for genuinely
unrepresentable values (roles, capacity, non-empty camera-plan absence).
Files: `scene_production_pipeline_service.py` (freeze call `:1952-1962`),
possibly `generation_contract.py` (router-scoped projection). Negative
controls: router batch with selection metadata → `{}` + evidence present;
non-router batch keeps full parameters; declared-path dispatch with evidence
passes; `:784` unprojected gate still refuses non-empty (phase_a test,
Tested).

### Ruling R4 (item 4 — record shape / rejected list)
**Recommend: option (B) only with the full negative-control battery and
explicit owner approval; otherwise (A), accepting that single-environment
scenes stay non-dispatchable until genuine alternates exist.**
Guardrails: never synthesize rejected identities; the exactly-one-approved
row, binding equality, digest, 64-hex fingerprint, and version-identity
checks stay untouched. Files: `runway_reference_projection.py`
(`:1017-1020` + selection-basis handling), F5 builder, generic projection
tests. Touches authorization semantics: **yes** — the only item besides F5
proper that does. Negative controls: §d list, including the new
`[]`-with-plural-candidates refusal.

### Sequencing (what can land before the generic authorization builder F5
without minting authority)

redefines authorization evidence and must be decided and landed *with* F5's
authority model, under the same approval. F5 proper (minting generic
`reference_projection_authorization`) stays last and blocking.
