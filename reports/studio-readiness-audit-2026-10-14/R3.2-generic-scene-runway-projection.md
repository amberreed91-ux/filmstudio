## 1. Problem and objective

R3.0's main functional blocker: `runway_reference_projection/v1` accepts only the frozen Scene 002
five-shape contract, so valid generic-scene reference configurations stop at the adapter boundary.
Objective: support explicitly defined generic reference shapes through the mocked adapter boundary
with all existing safety guarantees intact, preserving Scene 002 behavior byte-for-byte.

## 2. Trace (before editing)

- `project_runway_v1` → `_validate_v1_shape` (exact 5, exact roles/order, DRE/MAYA identity rules,
  enumerated omission of `alternate_angle`) → digest → record.
- `authorize_environment_reference` is already fully generic (exactly-one-environment, must equal the
  authorized identity) — no Scene 002 specifics. Only shape validation, the projector, the
  contract-row reader (exact-5), the authorized-entry (hardwired v1), and reconstruction (requires
  policy v1, replays v1) were Scene 002-locked.
- Adapter last mile: `_declared_reference_projection` → `project_authorized_environment` →
  `reconstruct_projected_request` → Router builder, with wire-vs-selection equality enforced.

## 3. Generic v2 contract (explicit, no Scene 002 identity anywhere)

- Shape: 1–4 canonical rows; ≥0 character rows (roles face/general/alternate_angle) + exactly 1
  setting row (role environment); unique non-empty ref_ids; non-empty target_ids; every row
  approved + canonical; composition/temporal/unknown roles rejected; >4 rejected as
  `invalid_canonical_count_or_shape` (caller narrows via designation — no silent ranking).
- Selection (enumerated): select all validated rows in frozen order; omit nothing; reason code
  `within_capacity_no_omission`. Coverage recorded per character target_id (`{id}:{count}`).
- Authorization, fingerprints, local-byte verification, materialization gating, expected-binding and
  digest-replay disciplines reused verbatim from v1.
