## 4. Implemented correction and rationale

**R4.3-C1 — durable per-job batch-authorization evidence** (closes G1, closes
G2's enumerability aspect). `generate_scene` now indexes the successful
preflight report by shot and stamps every created job's metadata with a compact
`batch_authorization` record: preflight name, project/scene, manifest
fingerprint, prepared snapshot id, 1-based batch position + batch size,
`authorized` verdict (fail-honest `unmapped` when a row is absent — never
claims authorization without a verdict), policy version, digest status, and the
confirmation-enforcement flag. The existing `reference_projection_authorization`
entry is preserved untouched; the Scene 002 protected loop is untouched.

Why this shape: no schema change (metadata column already exists), no gate
change (stamp is evidence, never an input to any check), idempotency-neutral
(the key hashes prompt/assets/parameters, never metadata), and
submit-authorization-neutral (durable-vs-memory metadata comparison holds
because the stamp is set before creation — proven by the 188-test neighboring
run passing, including the authorization and projection suites). Mid-batch
orphans are now enumerable from any single job's stamp, which is the smallest
complete fix for G2 without inventing save-on-failure semantics.

Files: `studio-backend/app/services/scene_production_pipeline_service.py`
(+map construction, +metadata call-site, +`_batch_authorized_job_metadata`
helper). Tests: `studio-backend/app/services/test_batch_authorization_evidence.py`
(5 tests: stamp correctness on all created jobs; positions/count/shared
fingerprint enumerability; projection-authorization preservation via the
prepared-mutator hook; enforcement-flag + unmapped-verdict helper units;
input non-mutation).
