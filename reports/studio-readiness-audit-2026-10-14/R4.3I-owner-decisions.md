### Backstop evidence (why A is safe)

- Storage choke-point gate: `provider == "runway_router"` rows persist **only**
  with full frozen-contract metadata (`creative_generation_contract`,
  `creative_generation_manifest`, fingerprint, digest, identity), else
  `RuntimeError("Runway Router jobs require complete frozen contract metadata")`
  (`storage.py:6325-6334`).
- Runtime-only statuses normalize at the same choke point: `submitted` →
  `pending`, `queued` → `pending`, etc. (`storage.py:25-30`, applied at
  :6227). No writer can leave a `submitted` row behind; genuinely invalid
  statuses still fail the CHECK (`storage.py:221`).

### Rationale for A

None of the five writers mints authority: #1 is pass-through, #2/#4/#5 only
move existing rows toward terminal/safe states, and #3 (the only one that
creates rows) fails closed at the storage gate for contract-less router rows.
Gating them would be dead authorization text around writes that cannot
authorize anything.

## D2 — Single-job digest revalidation (decision A: accept as by design)

### Options considered

- **(a) Accept as by design; pipeline-level guarantee only. [CHOSEN]**
- (b) Add confirmation-digest revalidation to single-job paths
  (e.g. `POST /jobs`).
- (c) Retire single-job creation paths.

### Read-only findings

- `POST /jobs` (`routes/render.py:273-292`) calls `create_job` with
  prompt/assets/parameters only — there is no `generation_contract` kwarg to
  pass, so a `runway_router` request raises `ValueError` before any actor,
  storage, or provider contact (`render.py:2168-2169`; second check at
  :2402-2403; request-actor/owner gates at :2171-2188; creation authority
  `authorize_runway_submission(..., require_durable=False)` at :2612-2623
  and :4262-4278).
- Persistence repeats the guarantee: contract-less router rows raise at
  `storage.py:6325-6334`.
- `retry_render` (`routes/render.py:402-410` → `retry_job`,
  `render.py:5099-5145`) loads via `get_job` and raises when missing
  (:5101-5103); the protected path reloads the durable row and reassigns
  `job = persisted` (:5109-5119); resubmission reuses the same id through
  `submit_job`, whose entry guards (:4331-4345) and direct-Runway submission
  disable (:4373-4395) plus the adapter authority gates (R4.3A §4) still
  apply. Retry is pinned to the persisted job — it creates nothing.
- Existing tests proving it:
  `app/services/test_non_pipeline_router_creation_fails_closed.py` (3 tests:
  router-without-contract fails closed incl. the production-queue entrypoint;
  non-router providers unaffected);
  `app/services/test_router_submission_reconciliation.py` retry tests
  (:193, :345, :361, :374, :394, :416, :484 — retry blocked/adopted per
  upstream evidence on the same durable row);
  `app/services/test_production_authorization_service.py:673` (retry
  re-enforces stale approval before provider contact).

### Rationale for A

Single-job paths *cannot* produce reference-bound router work — they fail
closed two layers deep (creation gate + storage gate) — so there is no
unconfirmed router work outside the pipeline to revalidate. Digest
revalidation there would be dead code implying those paths can do production
router work. Non-router providers intentionally carry weaker guarantees by
design (the capability gradient, R4.3A §10), not as a gap.

### What remains for D2

Nothing (accepted, by design). Re-evaluation trigger: the
`generation_contract=` grep tripwire (R4.3A §7) — if any future non-pipeline
caller passes a frozen contract, re-open.
