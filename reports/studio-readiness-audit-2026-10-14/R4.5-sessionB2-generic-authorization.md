- Never synthesized. The rejected list = live `_asset_rows(project_id, target_type="setting", target_id=setting_id)` rows of kind `environment` that are NOT the authorized anchor (approval `rejected`, or `candidate` not yet approved), enumerated at mint and recorded verbatim in `environment_basis` with their observed approval states.

- Acceptance consequence: the representative batch fixture must seed one genuine non-authorized environment row (e.g. a `rejected` candidate for the same setting) through the real persistence API — fixture data, explicitly labeled, not a synthesized identifier. Without it the truthful list is empty and the adapter's non-empty requirement correctly refuses.

### 7.7 Why this is not self-attestation

The record's binding digest equals a digest the pipeline also computes — but mint authority comes from two artifacts the pipeline cannot produce: (1) the creator's persisted confirmation row (`confirmation_id` + `confirmed_digest`, written only through `record_shot_confirmation` after server re-verification, scoped to exact project+shot); (2) the persisted canonical setting authority (universe location entity + approved anchor + live row enumeration) and the approved storyboard version (creator-approved blueprint). The pipeline proposes; persisted creator approvals dispose.
