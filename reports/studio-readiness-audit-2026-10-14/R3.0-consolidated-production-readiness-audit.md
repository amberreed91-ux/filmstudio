## 3. End-to-end architecture and data-flow trace

Reference creation → canonical authority → Desk confirmation → frozen binding → Gate → adapter delivery → outcome record:

1. **Creation:** uploads/URLs enter as `candidate`, non-canonical (`ReferenceAssetService.register_upload`, `add_reference_library_asset` rejects `canonical:true` with 400; Scene 002 exact pair has its own create/upload). Casting-generated portraits sync as `candidate`/`source_kind='generated'`/`canonical=False` (`reference_asset_service.py:983–1012`). Training requires `approved` — candidates fail closed (`visual_training_service.py:235–273`).
2. **Designation:** generic `designate_setting_reference_canonical` (`reference_asset_service.py:578`) enforces provenance (`verify_setting_entity_scope`), exact project/setting target, environment kind, approved state, usable image — all before any write — into exclusive transactional setter `set_setting_reference_canonical` (`storage.py:14128`); route `POST …/reference-library/setting/{target_id}/{ref_id}/canonical` (`reference_assets.py:308`); `confirm()` strips client `canonical`. Sync writes the consumer's setting-entity identity, never downgrades (`:760`, `:787`).
3. **Confirmation (single-shot):** Desk resolves via `GET …/shots/{shot_id}/reference-binding` → `resolve_shot_binding`, displays digest, requires explicit click (`ProductionDesk.tsx:410`), detects staleness against fresh resolution (`:415`), and hands only a matching digest to Previs via route state (`confirmedBindingHandoff.ts`). Server re-verifies every carried digest before the job-creation loop (`scene_production_pipeline_service.py:580–634` → `verify_confirmed_binding`, `:1192`). Reload drops the confirmation by design (re-confirm; server fails closed).
4. **Freezing:** `resolve_shot_binding` → `reference_binding_for_requirements` → digest; job creation persists `frozen_reference_binding` + digest into job metadata/initial parameters (`render.py:2211–2233`); `verify_frozen_reference_payload` (`reference_validation.py:447`) rejects malformed/empty/drifted bindings and URI mismatches against the payload.
5. **Gate:** creation-time `authorize_runway_submission` (`render.py:2612`, `:4262`, persisted as `job.metadata["production_authorization"]` with stage) plus adapter-side re-authorization against durable storage with binding-digest cross-check (`adapters/__init__.py:1750–1795`, `:1871`, last-mile revalidation `:2393`).
6. **Delivery:** `canonical_bindings_from_contract` → `project_authorized_environment` → `project_runway_v1` → fingerprint/materialize → `reconstruct_projected_request` → wire-equality check (`adapters/__init__.py:1743–1859`). **Shape gate:** `_validate_v1_shape` requires exactly the Scene 002 five (4 character + 1 setting, fixed roles/order); anything else fails `invalid_canonical_count_or_shape`.
7. **Outcome:** job rows carry project/scene/shot identity, frozen binding + digest, generation contract, authorization record, `router_execution` metadata (policy id/version, selected/omitted ids, fingerprints, digest); provider task id extracted (`_extract_task_id`) and recorded in normalized output metadata; failures recorded with reason codes; `render_attempts` carries per-shot prompt/provider/scores.

1. **[Blocker] No live Runway acceptance.** No confirmed provider acceptance for any binding shape. Impact: production readiness unprovable. Next: authorized live submit (Scene 002 shape first) with task-id + outcome capture.
2. **[Blocker] Generic scenes cannot deliver.** v1 projection enforces the Scene 002 five-shape; R2.3 generic anchors fail `invalid_canonical_count_or_shape` at the boundary. Fail-closed (safe) but a hard scope wall. Impact: generic production impossible until a generic projection policy exists (product decision + new policy, not a tweak).
3. **[Blocker] Full-suite verdict stale.** Phase 3: 4690/79; since then A (47 path), C (3), D1 (hang) remediated without a fresh full run; B/E/F/G/D-remainder status unknown in-suite. Impact: no trustworthy regression baseline. Next: fresh long-window full run, then triage delta.
4. **[Risk] Outcome traceability gaps.** Raw provider responses kept normalized-only; `render_attempts` keyed by `(shot_id, attempt_n)` with no project/job linkage — cross-shot or cross-job reconstruction needs manual joins. Impact: incident review friction, not authorization risk.
5. **[Risk, accepted] No durable uniqueness; state-only audit; storage-level Scene 002 fence absent.** Each contained (fail-closed resolver; observable flags; service/route refusal). Impact: none today; revisit only with new evidence.
6. **[Deferred by design]** Multi-shot confirmation, reload persistence. Impact: workflow scope only; Desk is honest about single-shot holding.
