## 2. Actual implementation and API changes

Backend (`scene_production_pipeline_service.py`):
- New `preflight_batch_authorization(*, project_id, scene_id, entries,
  shot_manifest, expected_digests) -> dict` (replaces
  `_verify_confirmed_reference_bindings`, which had exactly one caller and no
  direct test callers). Read-only: resolves/verifies without creating jobs or
  contacting providers. Per shot, in order: (1) shot-id integrity
  (`malformed_shot_id` / `duplicate_shot_id`); (2) Desk-confirmed digest via
  the existing `ReferenceAssetService.verify_confirmed_binding` with identical
  skip semantics (only shots present in the supplied map are verified);
  (3) upstream blockers (`upstream_blockers`, no invented failures);
  (4) creative-manifest membership (`missing_generation_contract`);
  (5) binding currency (`unapproved_reference`) and setting authority
  (`ambiguous_setting_authority` / `missing_setting_authority`);
  (6) projection policy — Scene 002 keeps its v1 authorization proof
  (presence + binding-digest match, `policy_version: "v1"`, no re-validation);
  generic `runway_router` shots are checked against their parsed frozen
  contract with the submit gate's exact rules (`unsupported_reference_role`,
  `unsupported_reference_capacity` at >4, `policy_version: "v2"`).
  Returns `{ready, project_id, scene_id, shot_count, passed_count,
  failed_count, digest_expectations, shots[]}` with per-shot
  `{shot_id, ok, failure_code, failure_category, message, policy_version,
  digest}`. Creator messages contain no credentials, paths, or payloads.
- `generate_scene` now calls it after the frozen-contract block and raises
  `ValidationError(stage="batch_authorization_preflight",
  failure_type="batch_authorization_preflight_rejected")` carrying the full
  report in metadata when `ready` is False. This is the single pre-execution
  boundary for both the protected and normal job-creation loops.

API (`app/routes/projects.py`, GET `generation-preflight`): additive
`"authorization"` field computed by the same service method with
`expected_digests=None` (Desk digests arrive at submit time). Still read-only:
no jobs, no providers, no state changes. Existing fields byte-identical.

Frontend (narrow, existing tokens/components only):
- `studioApi.ts`: `BatchAuthorizationShotResult` / `BatchAuthorizationReport`
  types; optional `authorization` on `GenerationPreflight` (backward
  compatible — absent means satisfied).
- `GenerationReadinessPanel.tsx`: generate gating ANDs
  `authorizationReady`; a refused batch renders BLOCKED (never ready) with a
  per-shot failure list (`preflight-authorization-failures`,
  `preflight-auth-shot-<id>`); the fresh-check-before-generate path also
  refuses when authorization fails.
- `PrevisRoom.tsx` final preflight gate and `useGenerationPreflightGuard`
  (status + `authorizeFinal`) treat a refused authorization as blocking for
  all shots (batch semantics). Also repaired a malformed
  `if (!fresh.ready)` return in the guard found during editing (missing
  object-close brace left a stray `}` — removed; `tsc` clean).

## 3. The precise preflight-to-execution boundary

`generate_scene`: consume → frozen-contract verification → **
`preflight_batch_authorization` → raise on `ready === False`** →
`per_shot_score_provider` → protected loop / main loop (`create_job` first
appears after). No job-creation statement precedes the raise; no speculative
create-then-delete; no provider contact inside preflight (only storage reads
via the binder and pure frozen-contract parsing). Downstream creation-time,
submit-time, and adapter-level checks are untouched and remain active.

## 4. Evidence that no job can be created before all shots pass

- Tests assert `render.created == []` and `render.jobs == {}` for stale-first,
  stale-last, wrong-shot-digest, and over-capacity end-to-end rejections, plus
  a `get_adapter` tripwire (raises on any provider-adapter resolution) active
  during rejection paths.
- A rejected batch leaves entries untouched (no partial writes).
- Preflight cannot be stricter than submission for Router shots: it applies
  the submit gate's exact rules to the submit gate's exact artifact (the
  frozen contract), only earlier. A dedicated passing-Router test guards
  against over-strictness.

## 8. Unresolved architecture constraints / historical failures

- Enforcement point is `generate_scene` only. Any future batch entrypoint
  that creates jobs without calling `preflight_batch_authorization` would
  bypass the guarantee — a grep for `create_job` call sites outside the
  pipeline should gate R4.2 scope.
- GET `generation-preflight` evaluates authorization without Desk digest
  expectations (`digest: "skipped_no_expectations"`) and against prepared
  (pre-consume) entries; POST submit-time evaluation is authoritative.
  The panel copy does not over-claim (“no jobs were created” appears only on
  actual failures).
- Historical failures left untouched per scope: cost-estimator expectation
  (G1) and phase6 fixture drift (G).
