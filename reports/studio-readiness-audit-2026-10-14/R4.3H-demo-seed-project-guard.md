## 3. Change made (service layer + thin route)

`studio-backend/app/services/demo_seed_service.py`:

- New module constant `DEMO_PROJECT_ID = "demo_studio_cinematic_001"`;
  `seed_demo_project` defaults to it (same value as before).
- First statement validates `(project_id or "").strip() == DEMO_PROJECT_ID`.
  On mismatch it emits a stage log (`demo_seed_rejected`, with `project_id`,
  `provider="demo_seed"`, `duration_ms`) and raises `ValidationError`
  (`error_type="validation_error"`, `stage="demo_seed"`,
  `metadata.code="demo_seed_non_demo_project_rejected"`) with a
  creator-facing message naming the expected demo project and stating the
  caller's project was left unchanged. Zero writes precede the raise.
- No business-logic change for the allowed ID; the seed body is byte-identical
  past the guard.

`studio-backend/app/routes/projects.py` (`seed_demo_project` route):

- Wraps the service call in `try/except StabilityError`, mapping
  `validation_error → 400` (same mapping the file already uses for character
  updates) with `detail=exc.to_dict()`. The route stays thin: no storage or
  provider access, no new logic.
