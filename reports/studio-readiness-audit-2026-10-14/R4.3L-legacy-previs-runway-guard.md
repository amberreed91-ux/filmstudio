# R4.3L — Legacy previs Runway guard (Policy A implementation)

Date: 2026-10-16 · Single isolated production-code task in batch · No live calls of any kind.

Owner decision (made): Policy A. The legacy non-canonical previs path
(`POST .../previs/generate-scene/{scene_id}`) rejects Runway-family providers
(`runway`, `runway_router`, `runway_direct`) with a clear 4xx before any job
exists, and leaves every other provider's behavior unchanged. Runway remains
the only approved production provider. No providers added, none enabled, no
live calls. Production render and revision behavior unchanged.

## 1. What changed

Backend (additive refusals only, mirroring the R4.3J canonical guard structure):

- `studio-backend/app/routes/previs_routes.py`
  - New `LEGACY_PREVIS_RUNWAY_PROVIDERS` (`runway`, `runway_router`, `runway_direct`)
    and `LEGACY_PREVIS_RUNWAY_REJECTION` message.
  - New `_validate_legacy_previs_provider()` raises HTTP 422 before any service
    call. Placed before the `try` so the 422 status survives (the generic
    handler below would otherwise convert it to 500 — found by test, fixed).
- `studio-backend/app/services/previs_service.py` (`PrevisService.generate_scene`)
  - New additive guard at method entry rejects the same three values with
    `ValidationError(stage="previs_generate",
    metadata={"rejected_provider", "code": "legacy_previs_runway_rejected"})`
    before storage, scene lookup, or `create_job`.
  - Message deliberately carries both the new creator guidance ("Runway is not
    used for previs; use simulated previs (instant, no cost)") and the prior
    enforcement vocabulary ("canonical scene pipeline's READY frozen contract;
    the standalone Previs path cannot authorize a mutable request"), so the two
    existing negative assertions keep matching with zero edits.
  - Untouched per mission: `PrevisImageService`, `render_production_package`,
    `render_revision`, `RenderService.create_job`, the R4.3J canonical guard,
    the standalone `runway_router` guard below the new block, the Scene 002 v1
    contract, Replit/Stitch.

Frontend (no picker redesign, no new features):

- New `studio-app/src/lib/legacyPrevisProvider.ts`: `resolveLegacyPrevisProvider()`
  maps Runway-family picker values to `"simulated"`, passes everything else
  through; `isLegacyPrevisRunwayPicker()` is case-insensitive.
- `studio-app/src/pages/PrevisRoom.tsx`: only the legacy previs call
  (`handleInitializeRender` → `generatePrevisScene`) uses the resolver. All
  other `renderProvider` uses (model catalog gate ~:566, preflight hooks,
  `GenerationReadinessPanel`, `CanonicalWorkflowPanel` production render/revision
  props) are byte-identical. When the picker holds a Runway-family value the UI
  shows the copy "Simulated previs: instant, no cost".

Tests (new files only; zero existing assertions edited):

- `studio-backend/tests/test_r43l_legacy_previs_runway_guard.py` (18 tests):
  service matrix over None/simulated/runway/runway_router/runway_direct,
  stable-code metadata, Runway-dead renderer control, other-provider
  passthrough (happyhorse/happyhorse-r2v/wan), route 422-before-service and
  allowed-passthrough.
- `studio-app/src/lib/legacyPrevisProvider.test.ts` (6 tests): Runway-family
  never forwarded; allowed values pass through.
